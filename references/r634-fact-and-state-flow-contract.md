# R6.34 事实与状态流合同

## 范围

R6.34 只修复两类系统漏检：人工接受的可见事实没有进入后续物料；一个供应商视频段以同一决定性接触开始和结束、却要求中间完成复位。不得借本合同改变模式、文案、段数、宫格数、宫格布局、参考图数量、供应商图片顺序、时长、费用或重试纪律。

## 人工接受的可见事实

`UNWANTED_ARROW_OR_DIAGRAM_MARK` 不改变故事事实，仍可使用 `scope=CURRENT_GRID_ONLY`。

符合 `*_COUNT_<实际>_INSTEAD_OF_<计划>` 的数量漂移会改变模型可见事实，不能使用 `CURRENT_GRID_ONLY`。人的接受文件必须逐字列出：

- `scope=DOWNSTREAM_FACT_PROPAGATION`；
- `propagation_policy=PROPAGATE_OBSERVED_FACT_DOWNSTREAM`；
- 从失败码确定性解析的 `accepted_deviations`。

控制器必须保留拒绝 QC、人的豁免原文和通过版 QC，并另外生成 `R6.34-ACCEPTED-DEVIATION-FACT-CONTRACT-1.0`。合同绑定上述三份证据以及原始/有效 JOB、原始/有效 SCENE_PLAN 的项目相对路径和 SHA256。有效物料只覆盖来源宫格及后续段的同一实体事实；P5、P6、P7 必须从项目账本解析，禁止凭聊天记忆替换数字。

文本传播必须由 `entity_id` 对应的 `physical_prop_specs.visual_signature` 建立作用域，只改写该实体的视觉签名、名称、状态行和包含该实体名词的局部数量短语。同一段文字中其它实体即使具有相同数字和量词也不得被改写；无法建立唯一实体签名或名词作用域时必须阻断，禁止对整个 JOB/P4 做全局数字替换。

同一项目中同一项目级实体若再次产生冲突数量，不得叠加第二个相互矛盾的事实；停止并选择唯一一次合并修正或新项目修订。

## 段内循环接触

对每张宫格逐实体检查第一格、中间格和末格。若第一格和末格的同一实体位于同一决定性接触位置，而任一中间格离开该位置，则状态是 A→B→A。奖励在狗嘴→收回手中→再次到狗嘴属于典型案例。

这种动作在现实中可能成立，但对于“整张宫格 + 首格占位”的当前视频适配器，首格强先验可能吞掉中间复位。P4 必须在任何 P5/P6/P8 外部调用前阻断，不能把它记为普通模型随机性。

修复原则是保持原段数、宫格数和任务数，把相邻段共享边界移动到复位完成后的状态，使新段从 B 单调推进到 A。上一段末格与下一段首格必须同时采用该共享 B 状态；不能只修改下一段而制造连续性跳变。

运行：

```powershell
python -B -X utf8 scripts/audit_r634_project_integrity.py --project-dir <project-dir>
```

只有 `SEGMENT_STATE_FLOW_AUDIT_R634.json` 为 `PASSED`、绑定当前有效 SCENE_PLAN 哈希并以 `VALIDATED` 进入项目账本，R6.34 才允许建立 P6 或 P7 包。

## 成本不变量

- 新增外部调用：0；
- 新增宫格：0；
- 新增供应商视频：0；
- 自动重试：0；
- 每宫格仍最多一次基线和一次合并修正；
- 人工批准仍是一份精确封印对应一次提交。

# 已验收生产模式与后续测试规则

## 1. 两个基线不能混用

| 项目 | M2-D 转发优先旁白二创 | M2-F 原声语义重绘 |
|---|---|---|
| 文案 | 默认保持源语言；按转发目标改表达，但源语义单元、因果与结果100%继承 | 原文逐字保留 |
| 画面来源 | 锁定文案与完整大场景语义 | 原文、原声时间和源视频大场景动作语义 |
| 源视频像素 | 不作为生图输入 | 不作为生图输入 |
| 声音 | 剪映“真人播客女”，全片 1.3 倍 | 完整原 MP3，固定 1.0 倍 |
| 时间权威 | 最终实测旁白 | 原 MP3 时间轴 |
| 视频对齐 | 视频服从最终旁白 | 视频服从原声 |
| 模型音轨 | 静音 | 静音 |
| 字幕 | 最终旁白 ASR 时间 + 批准文案纠字 | 原声 ASR 词时间 + 锁定原文 |

共同使用同一生产骨架：完整大动作场景、每段一张最小够用宫格、整张宫格一次生成、G01 建项目视觉锚点、G02+ 使用项目锚点和上一段末格、宫格加确定性首格提交 Grok、视频单段不低于 80 分、全片平均不低于 85 分、直接生成剪映草稿。

R6.16 的 M2-D 真实项目只证明视觉、时间和剪映装配路径；其口播存在未被源证据约束的扩写，因此不再作为“文案忠实度已认证”的证据。当前 M2-D 每个新项目都必须重新通过源内容继承门。

## 2. 新模式开始前必须先回答

1. 它继承 M2-D 还是 M2-F？只能选一个。
2. 文案保持、改写还是重新创作？
3. 声音是原声、后期旁白还是主角口播？
4. 唯一时间权威是什么？
5. 画面依据是源像素结构、源动作语义还是新文案语义？
6. 哪些人物、环境、物体、风格必须保持？哪些必须改变？
7. 供应商输入方式、秒数范围、比例和成本上限是什么？

任一答案改变路线、目标、文案、声音、时间权威、视觉权威、风格、比例、供应商适配器或成本策略，都新建项目修订；不得修改标签后继续使用旧 P3-P9。

## 3. 后续测试顺序

1. P1 只锁模式差异、输入、风格、声音、比例、供应商和成本。
2. P2 先建立全片证据；不凭文案常识补动作。
3. P3 先锁声音与时间权威，再规划画面。
4. P4 按完整大场景分段；不按 5 秒、6 秒、宫格容量或供应商整数秒反切内容。
5. P5 在调用前审计语义、动作顺序、状态终点、风格和 Prompt 血缘。
6. P6 整张宫格一次生成；只有模型渲染错误允许一次整张修正，修正后仍失败即停止。
7. P7 每段绑定唯一宫格、首格、动作路径和目标时长。
8. P8 每个上传和视频任务单独封印；一次批准只提交一次，不自动重试。
9. P9 先按声音时间轴调视频，再生成短字幕和直接剪映草稿，最后在剪映预览。

## 4. 诊断时先区分问题来源

- P2-P4 内容或动作不对：上游分析/模式合同问题。
- P4 正确但 P5 漏写或矛盾：Prompt 编译问题。
- Prompt 正确但宫格穿模、漂移、提前结果：ImageGen 模型问题。
- 宫格正确但视频未遵守动作或构图：视频模型问题；按 80 分容差审核。
- 声画不同步：先查时间权威、实测声音和 P9 调速，不先重做图或视频。
- 草稿缺轨、长字幕或素材丢失：P9 构建/可移植性问题。

不得因为一次模型抽卡就改工作流；也不得因为模型经常抽卡而放过可重现的系统错误。

## 5. 成本纪律

- 宫格按完整场景和必要节点决定，不固定格数，也不逐格生成。
- 先审计 Prompt 和引用图，再调用模型。
- 供应商整数秒只用于生成；最终长度服从声音。
- 不为了“可能更准”自动增加图片、视频任务或重试。
- 测试模式仍执行一次批准一次提交；批量批准只覆盖列明的封印。

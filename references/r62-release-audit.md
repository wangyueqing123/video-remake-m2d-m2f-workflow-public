## 结构结论

R6.2 已把此前最主要的结构漏洞改为机器可校验合同：

- `visual_plan_mode`、`provider_adapter_profile` 和 `provider_intent` 分离，场景规划不再由 Seedance/Grok 输入方式反向决定；
- 每个 `video_segment` 只能绑定一个专属 `grid`，每张宫格只能服务一个视频段；
- 全片总览宫格不得作为多个视频段共同的供应商输入；
- 视频段由完整动作和完整句子决定，固定秒数切片在 P1 和 P4 两层阻断；
- 2×2 仅为首格试生产默认值，正式布局由必要视觉节点选择最小够用的 2×2/3×3/4×4/5×5；
- Prompt 编译器按 `grid_id` 只读取当前段场景和内容义务，后续段结果不能泄漏；
- 每宫格一次基线和一次合并修正，同时受项目总预算控制；首张宫格 QC 未通过不能扩展后续宫格；
- P7 起始占位图必须由宫格第一格确定性裁切，并具有源图、裁切框、输出尺寸和哈希回执；
- P7 强制动作初态、完整路径、唯一交互通道、决定动作、结果、镜头、连续性和禁止替代；
- A 旁白与 B 主角口播具有不同说话者和口型策略合同；
- P8 正式区分 `ASSET_UPLOAD` 与 `VIDEO_API`，二者分别封印、批准和消费；
- Grok/KIE 适配器固定当前段宫格为第 1 项、第一格裁切占位图为第 2 项，并校验两项哈希与 P7 包完全一致；
- 同一视频段只允许一次资产上传和一次视频任务；超时只能查询，不能重投；
- R6.0、R6.1 和旧版项目均保留，R6.2 为独立可迁移目录。

## 环境与可迁移性

- 控制器、合同校验、Prompt 编译和项目审计使用 Python 3.10+ 标准库；
- 第一格裁切使用 Pillow，属于已检测到的本地图像能力；
- 当前机器 PyAV、faster-whisper、NumPy、Pillow、pytesseract、Tesseract 和 openpyxl 可用；
- ImageGen 和视频 API 保持运行时能力预检，凭证不进入 Skill 或项目包；
- 所有永久血缘使用项目相对路径和 SHA256；
- 新任务/新电脑重新开启执行会话，历史审批不会成为实时调用授权。

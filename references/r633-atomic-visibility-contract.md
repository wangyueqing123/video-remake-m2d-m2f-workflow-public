# R6.33 原子可见性合同

本版本只修复“容器仍可见、内容物被遮挡”被错误建模成同一个可见性实体的问题，不改变任何生产或成本路径。

## 1. 原子可见性单位

`physical_prop_specs` 中每一项必须描述一个在任意单格中只能整体可见或整体不可见的实体，并声明 `visibility_unit: ATOMIC`。

如果两个部分可能具有不同可见性、数量、位置或状态，必须拆成不同 `entity_id`。典型例子：

- 浅盘仍露出盘沿、盘内零食被手遮住：浅盘与零食必须分开；
- 笼门可见、门后的狗被遮挡：门与狗必须分开；
- 包装可见、包装内物品不可见：包装与内容物必须分开。

禁止用“浅盘和盘内零食”“笼子和笼内动物”等复合签名承载会独立变化的可见性。

## 2. P1、P4、P5 继承

- P1 使用 `R6.33-VISUAL-STATE-CONTRACT-1.0`；每项规格含唯一 `entity_id`、`count_unit`、`visual_signature` 和 `visibility_unit=ATOMIC`。
- P4 每个对应实体逐字继承这三个渲染字段；容器移动、内容物遮挡和奖励递送分别记账。
- P5 若某实体 `visible=false`，不得同时要求它的边缘、局部、支撑接触或外观可见；若需要看见局部，说明实体划分错误，必须回 P1 新建项目修订，不能靠 Prompt 修辞掩盖。

## 3. 成本与兼容

- 不新增宫格、格子、图片、参考图、上传、视频任务或重试。
- 已通过旧版本解释的历史项目保持冻结。
- 本门禁在首次外部生成前执行；发现冲突只重建上游合同，不消耗 ImageGen 预算。

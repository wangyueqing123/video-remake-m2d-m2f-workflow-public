# R6.21 语义 Prompt 审计合同

## 目的

本合同解决“P4 计划正确，但 P5 只复制一段自然语言，导致模型在错误格提前显示终态”的系统漏洞。审计验证的是 P4 到 Prompt 的语义编译完整性，不评价 ImageGen 最终渲染能力。

## 权威与优先级

1. P4 逐格状态账本是唯一结构权威。
2. 当前格字段证明高于场景概括、动作修饰词与全段终态要求。
3. `prompt_lock` 只是一个字段，不能替代 `visible`、`count` 和 `location`。
4. P6 输出是否遵守 Prompt 由 P6 QC 判断；不得把模型渲染失败反写成 P5 通过或失败。

## 每格证明

每个 `in_state_table=true` 的实体必须在当前格中证明：

- 自然语言状态；
- `visible=true` 时的直接可见证据，或 `visible=false` 时的完全不可见证据；
- 数量及不得复制的约束；
- 当前格位置。

若实体位于狗嘴且 `visible=true`，必须明确“有可辨识部分露在狗嘴外”，避免模型把“在嘴里”解释为完全遮挡。

## 相邻边界证明

相邻格只要状态、可见性、数量或位置发生变化，就生成一条唯一边界对照：前格结束前仍保持旧状态，只有后格才可首次进入新状态，并禁止后续回退。没有变化时不生成冗余边界。

## 独立重算

`semantic_prompt_audit()` 必须从已绑定的 JOB、P4 和实际 Prompt 重算：

- 预期与已验证状态证明数量；
- 每条状态证明哈希；
- 每条相邻边界证明哈希；
- 整体语义指纹；
- 缺失、重复或冲突问题。

P6 调用包验证器必须再次重算并与包内审计对象完全相等。保存的 `status=PASSED` 不构成授权。

## 失败归因

- P4 本身状态、顺序或字段错误：`UPSTREAM_PLAN`，回退 P4。
- P4 正确但 Prompt 缺字段、提前终态或边界丢失：`PROMPT_COMPILER`，修系统后重编 P5。
- Prompt 和审计均正确，参考图角色错误：`REFERENCE_ROLE`。
- 上述均正确但成图不服从：`MODEL_RENDERING`，才可按预算使用一次整张合并修正或降级。

任何失败都不得自动调用 ImageGen。

若旧版基线已经消耗、后来证明根因是 `PROMPT_COMPILER`，新项目修订必须保留该次提交、QC 和成本证据。只有机器证明系统修复已应用、P5 已在新版本重编且语义审计通过时，才可使用该宫格原有的唯一 correction 额度；不得把它伪称为纯模型抽卡，也不得重置 baseline 额度。

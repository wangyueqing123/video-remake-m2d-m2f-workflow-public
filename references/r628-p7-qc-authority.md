# R6.28 P7 权威 QC 衔接合同

R6.28 只修复 R6.27 零调用复审项目无法进入 P7 的下游衔接，不改变场景、宫格、Prompt、首格、上传数组、视频任务、时长、声音、费用或重试纪律。

P7 为每个宫格解析唯一权威 `PASSED` QC：普通宫格只接受 `qc_records` 中与 `grid_id`、`segment_id`、输出路径和输出哈希完全一致的通过记录；R6.27 迁移形成的 G01 只接受 `historical_revision.anchor_origin_historical_qc` 中的零调用复审证明。不得把历史拒绝记录改写为通过，不得复制改名 QC，不得让多个通过记录竞争权威。

视频 Prompt 的动作时间节点始终来自当前段唯一宫格的逐格时间：从前一格时间移动到当前格时间，并以当前格可见状态为节点终点。段级 `action_nodes` 继续负责证明整段覆盖，但不能覆盖或压缩逐格节点。

历史 G01 证明必须同时重验：固定来源类型、文件哈希、G01/V01 身份、原宫格路径和哈希、`provider_calls=0`、物理 QC 复用和颜色 QC 重算。任一字段漂移即在裁切首格和上传前阻断。

R6.27 项目必须迁移到独立 R6.28 项目目录，保留原审批、提交、拒绝 QC、通过 QC、预算和媒体哈希；迁移不得产生任何外部调用。P7 生成后，P8 资产上传和视频任务仍分别建立新封印并等待精确人工批准。

若来源项目早于 R6.24、P3 尚未登记源事件血缘，迁移必须接收一份基于完整 `FRAME_INDEX` 和事件边界人工审阅的 `R6.28-SOURCE-EVENT-REAUDIT-INPUT-1.0`。系统只在独立审计副本中给原宏场景增加 `change_policy` 与 `source_event_ids`，其余字段逐字保持；原 P3/P4/P5/P6 及其哈希不得改写。事件证据、审计宏场景、输入复本和哈希必须进入迁移账本，P7 每次重新验证。缺失或篡改时阻断。

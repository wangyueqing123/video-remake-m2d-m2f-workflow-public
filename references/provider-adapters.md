# R6.7 供应商适配器合同

## R6.22 供应商任务身份回执（最高门禁）

创建任务成功不等于任务已经属于当前项目。任何供应商 Task ID 在进入项目账本前，必须保存原始 `recordInfo` JSON，并由 `verify_r622_provider_task_identity.py` 重算以下全部字段：

- 精确模型名；
- Prompt 的 UTF-8 SHA256；
- `image_urls` 的完整内容和顺序；
- `duration`、`aspect_ratio`、`resolution`；
- 任务创建时间不早于当前封印的人工批准时间；
- Task ID、包哈希、封印、批准、段 ID 和资源 ID 的完整血缘。

日志截图只可证明页面当时可见内容，不能单独证明任务身份；“时长相同”“位于日志顶部”“看起来是刚生成”均不是身份依据。控制器在 R6.22 中必须拒绝没有 `PASSED` 身份回执的 `VIDEO_API` 和 `VIDEO_API_RECOVERY` 消费。

适配器只决定如何提交已批准物料，不能改变路线权限、场景、动作、时长或宫格规划。

## `GROK_KIE_GRID_FIRST_PLACEHOLDER_SECOND`

当前 KIE/Grok 测试约定：

1. `image_urls[0]`：当前视频段的完整动作宫格；
2. `image_urls[1]`：从该宫格第一格确定性裁出的起始占位图；
3. Prompt 明确要求生成普通单画面视频，不得生成分屏、拼贴、边框或镜头在格子间移动；
4. 数组只能包含当前段物料，不能包含全片总览宫格或其它段宫格；
5. 起始占位图不能重新生成，必须能回溯到宫格第一格的哈希和裁切合同。

若宫格宽高不能被布局边数整除，适配器仍使用左上首格：每格宽高分别向下取整，余像素留在整图右缘/下缘。禁止为满足整除而缩放、拉伸、补边、重绘或再次调用 ImageGen；P7 包必须携带可复核的裁切回执。

这是当前项目的适配器合同，不等同于声称第三方 API 官方定义了两个硬槽位。精确端点语义必须在 P8 用当时接口证据锁定。

R6.4 不把任何供应商的原生对白或口型当作交付义务。所有适配器的默认 Prompt 均声明无对白、无需口型；生成音轨在后期忽略或替换。

## `GROK_WEB_GRID_PLUS_FIRST_FRAME`

只用于网页明确提供独立首帧槽和参考图槽的界面。首帧仍从宫格第一格裁出；完整宫格进入参考槽。不能把网页能力自动套用到 API 数组。

## `SEEDANCE_GRID_ONLY`

只上传当前段完整宫格。宫格第一格代表预期起始状态。Prompt 禁止拼贴视频。若界面没有格子-时间硬绑定，就只能称为顺序参考，不能声称精确时间码控制。

## `ORDERED_KEYFRAMES`

使用独立全帧关键帧，不使用拼贴宫格。必须记录真实能力等级：

- `HARD_TIMECODE_BINDING`：供应商明确支持每帧时间码；
- `HARD_SEQUENCE_BINDING`：顺序硬绑定但时间不硬绑定；
- `SOFT_PROMPT_ORDER`：只有通用图片数组和 Prompt 顺序。

图片数量不决定视频秒数，时长仍由完整动作和句子决定。

## P8 封印字段

每次请求封印：供应商、精确模型、端点、模式、当前段 ID、当前段宫格 ID、按顺序的资产 URL 与角色、Prompt 哈希、时长、分辨率、成本、调用序号、幂等键、`auto_retry=false`。

时长必须由上游批准段长派生，不能由适配器设置默认值：`duration_s=ceil(segment.target_end_s-segment.target_start_s)`。适配器只核验供应商当前支持范围和粒度；若供应商不支持派生秒数则在提交前阻断或在完整动作边界重新规划，不能静默回退到固定5秒。成本按锁定的逐秒单价计算。

上传和视频创建是两个不同调用：

- `ASSET_UPLOAD` 只发送文件，不创建视频；
- `VIDEO_API` 创建视频任务。
- `VIDEO_API_RECOVERY` 只用于认证供应商日志已证明原请求没有创建任务的异常恢复；它不是自动重试，也不能复用原权限。

两者都需要各自审批。超时先查询，不允许重复提交。

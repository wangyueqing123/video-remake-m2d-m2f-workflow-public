# R6.27 零调用接续合同

## 目的

解决一种单一历史断点：G01 已生成且物理 QC 全部通过，但因旧版没有把彩色道具登记成“颜色 + 对象”的作用域化强调色而被拒绝；R6.26 能证明旧图合格，却不能合法继续 G02。

## 适用条件

- 源项目版本为 R6.23–R6.26，状态为 `BLOCKED_P0`。
- G01 恰好存在一次基线提交和一次拒绝 QC。
- 拒绝原因只属于旧版强调色声明冲突。
- 布局、比例、时序、场景隔离、连续性、状态账本、拓扑和无文字检查全部通过。
- 原输出、原 QC、原提交和原预算哈希完整。

任何动作、拓扑、接触、文字、比例或场景错误都不适用本迁移。

## 确定性迁移

运行：

```text
python -B scripts/migrate_r626_zero_call_continuation.py --source-project <source> --destination-project <new-revision>
```

迁移必须：

1. 复制到新的独立项目目录，不改写源项目。
2. 保存源状态、源 JOB、源拒绝 QC 和旧颜色审计。
3. 只补充由既有道具描述确定性推导出的作用域化强调色。
4. 保留已经提交的 G01 P5 Prompt 与审计原件；只为尚未提交的后续宫格重新编译当前 P5 Prompt、审计和待审回执。
5. 对原 G01 重算命名强调色像素审计；复用旧 QC 中已经通过的物理检查。
6. 建立独立的历史通过 QC、项目视觉锚点和确定性末格回执。
7. 保留原审批、原提交、原拒绝 QC 与预算消耗；不得把旧审批改成当前授权。
8. 将下一安全动作设为准备 G02 调用包，保持 `provider_call_authorized=false`。

迁移全过程的 ImageGen、上传和视频 API 调用数必须为 0。

2×2 基线 Prompt 的内部预算为 6,600 字符，并额外保留 1,600 字符给唯一一次合并修正。该数值来自已成功执行的本地生产 Prompt，不宣称是 ImageGen 官方上限；不得再把基线错误压缩到 5,000 字符而阻断已验证场景合同。

## G02 接续门

G02 调用包只能在以下条件同时成立时建立：

- 历史通过 QC 的文件、哈希、G01 输出和四项参考提升布尔值全部重验通过。
- 项目视觉锚点合同绑定同一 G01 和同一历史通过 QC。
- G01 末格是确定性右下格裁切且回执通过。
- G02 当前版 P5 Prompt、Prompt 审计、待审回执和视觉锚点复审均为 `VALIDATED`。
- 调用引用仍恰好为 `PROJECT_VISUAL_ANCHOR` 与 `PREVIOUS_SEGMENT_END_STATE`。

满足以上条件只允许进入 `WAIT_REVIEW`，不等于允许调用。必须为 G02 新建封印，并获得与封印和调用包哈希逐字匹配的人类批准。

## 成本不变量

- 不重生 G01。
- 不新增宫格、首格、上传或视频任务。
- 不复活历史审批。
- 不自动重试。
- G02 仍只允许一次整张宫格基线；模型失败仍按原最高成本原则处理。

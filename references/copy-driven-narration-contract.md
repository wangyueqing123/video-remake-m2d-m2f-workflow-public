# R6.15 文案驱动旁白与画面合同

本合同只用于 `POST_DUB_NARRATION + NARRATION_MASTER`。

M2-D 在使用本合同前，必须先通过 [源内容继承合同](source-content-inheritance-contract.md)。旁白时间合同只决定“怎么测时”，不能授权换语言、添加事实、改变动作顺序或省略强制语义单元。

1. P3 先锁定整条成片唯一声音档案、唯一语速和完整旁白文案。当前已校准档案是剪映“真人播客女”、1.3 倍；公式系数已经包含该语速，不得再次除以或乘以 1.3。
   R6.36 必须再按交付语言选择计时模型：中文逐字符，英文逐词；其它语言没有登记模型时阻断。
2. 尚未调用最终 TTS 时，允许使用 `CALIBRATED_VOICE_ESTIMATE` 规划视频。它是生成前的创作时间权威，不冒充最终音频实测。
3. 每个完整动作场景的创意时长由该段文案估时决定。动作路径必须在同一时长内完成，并在末端给出可见结果；禁止拿旧视频动作速度反过来延长文案。
4. 每个分句必须建立至少一个“画面义务”，并写成可拍摄证据。抽象含义、否定、安全规则和结果都不能只留在文案中。
5. P4 的场景、动作节点、宫格关键状态与 P7 Prompt 必须逐级继承这些义务。未映射、漏掉终态、动作节点越过段落截止时间都阻断。
6. 当前视频供应商能力按最短 1 秒、1 秒递增处理：`provider_request_duration_s = ceil(creative_target_duration_s)`。3.54 秒请求 4 秒，2.84 秒请求 3 秒；禁止统一 5 秒。
7. P8 生成素材可以比创意时长多出不足 1 秒的尾量，P9 只裁剪或轻调视频来服从最终旁白；禁止逐句改变旁白语速。
8. 最终剪辑或导出前必须生成 `MEASURED_FINAL_VOICE`，用真实 TTS 音频或编辑器时间戳替换预估并完成对齐。若实测偏差使动作无法自然容纳，应返回 P4 重新规划，不得偷偷变速填空。

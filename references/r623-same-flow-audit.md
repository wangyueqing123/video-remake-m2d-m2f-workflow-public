# R6.23 同流程结构性审计

## 不改变的流程

R6.23 不改变 R6.22 的场景划分、宫格数量、图像生成次数、Grok 图片顺序、视频任务数量、时长公式、声音权威和剪辑路径。`assets/r623-flow-invariants.json` 是机器可读的冻结合同。

## 本轮真实失败暴露出的实现漏洞

1. P7 没有唯一的正式视频 Prompt 编译器。真实项目 Prompt 由运行过程直接写入，测试也只创建一段示例文本，因此 P4 正确并不能证明 P7 Prompt 被一致地编译。
2. 适配器要求 Prompt 禁止分屏，但没有把“单画面优先于复刻参考布局”建成可反向验证的首段合同。
3. P8 QC 依赖人工发现持续宫格/分屏，没有独立机器取证回执；系统无法证明在评分前已经检查布局硬错。
4. 供应商身份在 R6.22 已修复，但 Prompt 审计、布局取证和身份回执没有形成一个连续的 P7→P8 证据链。
5. P9 旧构建器只读取文件名匹配且声明 `PASSED` 的视频 QC，未把 Prompt、供应商任务身份、布局取证和输出哈希统一验签；过期或被改写的通过文件存在进入草稿的可能。
6. 当前 V02 的精确 Prompt 已明确禁止分屏，供应商仍输出持续 2×2 画面，因此该次具体输出属于模型渲染失败；系统问题不是“允许它通过”，而是缺少更早、更一致的编译与机器硬拒绝证据。

## 修复策略

- 由 `compile_r623_video_prompt.py` 从 P1 身份/风格、P4 动作节点与 P7 段合同编译唯一 Prompt。
- Prompt 第一段固定输入角色和单画面绝对优先级；后续只表达当前段动作、状态、时间和禁止项。
- 由 `validate_r623_video_prompt_audit.py` 重算 Prompt 与所有上游字段，不接受操作者自报通过。
- 由 `inspect_r623_video_layout.py` 对输出抽帧，形成持续边界机器证据；疑似或确定分屏均不能直接进入通过 QC。
- 由 `validate_r623_video_qc.py` 把正式 QC、布局取证、正式 Prompt 审计、供应商任务身份和输出媒体绑定成 `Vxx_VIDEO_QC_GATE_R623.json`。R6.23 的 P9 构建器必须重算全部哈希和校验结果；只有单独一个 `PASSED` QC 文件时必须拒绝。
- 保留人的最终语义判断。机器检测只增加硬拒绝证据，不自动创建修正任务。

## 成本结论

这些修改全部发生在本地编译、校验和抽帧，不增加 ImageGen、上传或 Grok 任务。模型失败后的修正仍沿用原合同：最多一次、重新封印、重新人工批准、不自动执行。
